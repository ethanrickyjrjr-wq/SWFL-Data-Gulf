# Design Reference — SWFL Data Gulf Design System

> **THIS IS NOT A LANDING PAGE. THIS IS NOT PRODUCTION CODE.**
> This folder is a reference artifact generated by Claude Design. Builders
> reference it for creative direction — they do not ship it as-is.

---

## What this is

A static design system built by Claude Design to establish:

1. **Chart output in conversation** ← the most important thing here
   - See `ui_kits/charts/` for the actual components (ChatCards.jsx, CorridorDetail.jsx, etc.)
   - See `ui_kits/charts/index.html` to open the chat preview in a browser
   - These show how data surfaces inline in an AI conversation — what the user actually sees when Brains responds

2. **Color palette and tokens**
   - `colors_and_type.css` — the full design token file
   - `brand-export/Colors_*.html` — each color role as a standalone HTML page
   - Colors are good direction, not locked. Change them.

3. **Logo / mark direction**
   - `assets/mark.svg` + `assets/wordmark.svg` — the proposed mark
   - `brand-export/Brand_Mark.html` + `brand-export/Brand_Wordmark.html` — rendered
   - Logo is good direction, not locked. Change it.

4. **Component ideas** (buttons, cards, trend indicators, source chips, etc.)
   - `brand-export/Component_*.html` — each component as a standalone HTML
   - Use as visual reference for what the Brains output surface could look like

---

## What builders should actually do with this

- Open `ui_kits/charts/index.html` in a browser — this is the primary reference
- Open `ui_kits/report/index.html` — this is the report page view
- Pull CSS variables from `colors_and_type.css` into the actual codebase
- Reference `brand-export/` HTML files for component look and feel
- Check `screenshots/` for static snapshots of all the above

**Do not copy-paste these components directly into production.** Claude Design
writes mostly static HTML/CSS. The animation quality and interactivity are
illustrative. Take the visual direction, re-implement in the project's stack
(Next.js + Tailwind).

## What Claude Design is bad at

- Animations. Most are placeholder or broken. The motion rules were
  documented in the original prompts but Claude Design implementation is
  inconsistent. Treat any animation as directional only.
- Real interactivity. Charts use static data. Swap in real data from the
  brain pipeline.
- Responsive layout. Everything was designed desktop-first.

The **visual design** (colors, typography, hierarchy, component shape) is
where Claude Design earns its keep. That's the reference.
